# 开发与协作指南

面向修改代码和维护项目的人。使用入口及目录说明见 [项目首页](../README.md)。以下命令均在项目根目录执行。

## 已有功能

- 3 张 / 5 张 / 6 张图片拼接，切换数量时保留已添加的图片。
- 三拼采用规整的 V 形斜切布局：三块等面积、左右对称，中间上宽下窄。
- 三拼可切换平行斜切布局：两条直线同向倾斜且互相平行，三块等面积。
- 三拼可切换六边形聚焦布局：中间为六边形，左右对称，两侧分割线在中部折转；扣除留白后三块面积相等。
- 五拼使用中间梯形模板：中间一张，左右各两张斜切拼接。
- 六拼使用中心汇聚模板：上下两排各三张，斜线与横向分割线在中心汇合。
- 批量选择和拖入图片；点击缩略图或画布位置可添加、替换。
- 调整顺序、移除图片、清空图片。
- 调整比例、画布宽高（100–6000 px）、间距、背景颜色。
- 居中裁切填满 / 完整显示两种适配方式。
- 全部位置填满后，按设置的像素尺寸导出 PNG 或 JPG。
- 本地处理，不上传图片；刷新或关闭网页会清除当前工作状态。

## 模板与设置

三拼有 V 形斜切、平行斜切、六边形聚焦三种模板，初始尺寸为 1200 × 900 px。五拼、六拼分别采用中间梯形、中心汇聚结构，初始宽幅尺寸为 2300 × 979 px。各数量模式会记住当前网页会话中的画布宽高和布局选择。

图片共用最多六个位置；切换到较少图片的模式会保留其余位置，切回即可继续使用。“清空”会清除所有位置，包括当前模式未显示的位置。

预设比例为 3:4、1:1、4:3 和宽幅；前三种会将宽度设为 1200 px，宽幅设为 2300 × 979 px。“自定义”只切换选中状态，宽高需手动输入。间距初始为 12 px，最高 80 px，实际可用上限随画布尺寸和模板收紧。适配方式、背景颜色和间距在各模式间共用。

“重置”在任意模式下均将画布恢复到 1200 × 900 px、12 px 间距、居中裁切和白色背景，保留图片与当前布局。

无间距时，顶边分割点为宽度的 1/6、5/6，两条直线在底边中点汇合，三块面积各占 1/3。增加间距时，程序会对称微调顶边分割点，保证扣除留白后三张图片分区的面积仍相等。

平行斜切的两条线从上往下向左倾斜，水平偏移量为画布宽度的 24%。程序保持两条线平行，并根据间距调整位置，保证扣除留白后的三块分区等面积。切换模板时保留已添加的图片；切换到五拼再返回三拼时，会恢复上次选择的三拼模板。

五拼、六拼按固定分区比例制作，不强制各块等面积。五拼的图片顺序为左上、左下、中间、右上、右下；六拼为上排从左到右、下排从左到右。三拼六边形仍保持左右对称、三块等面积。

## 模板实现与扩展

`assets/js/app.js` 中的 `TEMPLATES` 定义布局，支持三种接口：

- `cells(count)`：返回 `{ x, y, w, h }` 数组，使用 0–1 的归一化坐标。
- `polygons(count)`：返回凸多边形顶点数组，使用 0–1 的归一化坐标，由通用逻辑计算留白。
- `regions()`：返回 `{ x, y, w, h, points }` 数组，直接提供已经处理间距的像素区域。六边形聚焦、五拼、六拼使用此接口；其中六边形两侧包含内凹折点。

顶点按画布上的顺时针顺序排列。`cellRegions()` 统一生成区域，供预览、导出和点击检测使用；点击检测支持凹多边形，斜边间距按垂直距离计算。填满模式按包围盒居中裁切；完整显示模式结合重心与边界计算照片尺寸。

添加模板时同步维护 `TEMPLATES`、`state.layouts`（需要改变默认布局时）、`index.html` 中的模板按钮，以及 `assets/css/styles.css` 中的图标和布局样式。代码中还保留基础网格、横排、竖排模板定义，当前页面没有这些模板的选择入口。

预览画布最长边限制为 1600 px，以减少绘制开销；导出使用用户设定的完整像素尺寸。

## 格式说明

GIF 等动图导出为静态图片；HEIC 等格式能否读取取决于浏览器，读取失败时网页会显示提示。PNG 适合清晰的图文，JPG 适合照片。

## 开发验证

无需构建步骤。开发检查使用 Node.js 24，安装后在项目根目录执行：

```sh
node --check assets/js/app.js
node scripts/check-project.mjs
node --test scripts/check-project.test.mjs
```

GitHub Actions 会在推送、创建或更新 PR 时执行上述检查，也支持在 Actions 页面手动运行。检查包含 JavaScript 语法、HTML 引用的本地资源、重复元素 ID、`assets/js/app.js` 中字面量 `$("id")` 对应的元素，以及 Markdown 普通内联链接和图片引用的本地文件。外部网址和页面锚点不做联网或内容有效性检查。

PR 的 Checks 区域会显示 `Project checks` 的结果；失败时点击详情查看错误。仓库的 `main` 已启用分支保护：必须通过 PR、至少另一位协作者批准 1 次、`Project checks` 通过且分支与 `main` 保持同步，所有审查讨论解决后才能合并。审查后追加修改会使旧批准失效；管理员也受这些规则约束，并禁止强制推送及删除 `main`。

两人协作流程：创建功能分支 → 修改并运行检查 → 推送分支并创建 PR → 另一人审查 → 合并到 `main`。第二位开发者需要先被仓库管理员加入协作者并接受邀请；PR 作者不能批准自己的 PR。分支保护是 GitHub 仓库设置，复制或派生仓库后需要单独配置。

当前 CI 是静态检查及检查器自身的测试，尚未包含图片加载、Canvas 绘制或导出的浏览器功能测试。

修改后在浏览器中检查三种图片数量和五种布局、图片添加/替换/排序/清空、模式切换后的状态恢复、尺寸与间距调整，并分别导出 PNG/JPG 核对实际像素尺寸。修改几何计算时还需检查三拼等面积、斜边间距、凹多边形点击和两种适配方式。
